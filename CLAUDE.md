# Checkmatela

A chess-themed formal wear e-commerce concept site. Static HTML/CSS/JS, no build step, no framework, no backend — every page is opened/served as-is.

- **Local path:** `/Users/barbodp/Suit Business`
- **GitHub:** https://github.com/barbodp/checkmatela (branch `main`)
- **Live site:** https://checkmatela.vercel.app

## Workflow (always follow this)

1. Make changes locally.
2. `git add -A && git commit -m "..."` — every meaningful round of changes gets its own commit. Keep the full version history in git; don't squash/rewrite it.
3. `git push origin main`.
4. That's it — **Vercel is linked to the GitHub repo and auto-deploys `main` to production on every push.** Do not run manual `vercel --prod` deploys for routine changes.

## Design system

- **Theme:** light/ivory base (`--paper`) with a real black-and-white checkerboard motif (hero, footer strip, category banners) — not the dark theme it started as.
- **Palette:** pine green `--pine` (primary accent, buttons, links), brass/gold `--brass` (metallic accent), burgundy `--burgundy` (jewel accent, prices, swatches). Full token list at the top of `css/style.css`.
- **Fonts — ONE typeface site-wide:** Cormorant Garamond only (the sole Google Font loaded). `--sans` and `--mono` in `css/style.css` are aliases of `--serif`, so never introduce another family. Because Cormorant is light and small, `html` is 112.5% and small UI text (nav, buttons, labels, tables, forms) gets weight 600–700 in the final "ONE TYPEFACE" block. The Stripe-style labels (`[ bracketed ]` CTAs, underlined small-caps eyebrows) are kept, now set in Cormorant. The rest of the stripe.press experiment (dashed rules, grain, slash-numeral index, floating-model chapter) lives only on the unmerged `editorial-preview` branch.
- **Chess glyphs:** hand-built uniform Staunton-style SVG symbols (king/queen/bishop/knight/rook/pawn) defined inline in each page's `<svg><defs>` block — consistent base/collar/stem proportions modeled on a real Staunton set. Don't reintroduce the old crude/inconsistent glyph shapes.
- **CSS cache-busting:** `css/style.css?v=N` query param on every page — bump `N` on every CSS change and update it across *all* HTML files (`sed` one-liner) **and** `CSS_VERSION` in `tools/gen_pawn_pages.py`, or browsers will serve stale styles. Currently **v=73**. `css/style.css` is one long file made of appended blocks — when replacing a block, replace only that block's span (an earlier slicing edit once deleted the blocks after it).

### Pricing (repriced 2026-09-30 — cost-based, not arbitrary)
The user gave a real unit cost (~$45–48 to produce a suit, kids or men's, same either way) and wants to compete on accessible, repeat-purchase pricing rather than one-time luxury pricing — explicitly to attract groomsmen parties and men who buy suits often, not just once. King suits were repriced from $795–975 down to **$179–249** (10 products in `tools/catalog/king.json`, each individually mapped — don't reset them to a flat number) and Pawn from $89–139 up to **$115–159** (in `tools/gen_pawn_pages.py`'s `LINES`). Both ranges were checked against the real cost stack (COGS + packaging + free-swatch amortization + free-exchange/return cost + one free round of alterations) and land at a healthy 45–74% margin — see the "Formalwear competitor return policies" and "Formalwear return fraud risks" research reports (if still on disk in the session that made them) for the full math and competitor benchmarking (Modern Groom $210–260, Indochino ~$330–599) that this was based on. **Bishop (accessories) and Rook (shoes) have NOT been repriced** — no real cost data exists for them yet. Remind the user to revisit their pricing (same cost-based method) once real cost numbers exist or new products are added to those two categories.

Prices are otherwise invented placeholders (the concept site has no real backend) — tell the user if asked.
The main nav has a hover dropdown under "Pawn — Kids" (all pages) linking to the four pages; on mobile it's a static inline list.

### Tools (`tools/`)
Run from the repo root; they need `pip install --user pillow numpy scipy` (numpy/scipy are only for the cutouts).
- `process_pawn_images.py` — raw `~/Downloads/Magen Kids/...` → `assets/img/pawn/.../{model,plain,thumb}-N.jpg`.
- `make_hero_cutouts.py` (+ `cutlib.py`) — background removal for the hero figures. The kid photos are AI-style renders on a noisy near-white background; white shirts must survive, so it flood-fills only *neutral, near-white* pixels connected to the border, then also removes enclosed background pockets (between arm and torso) whose colour matches the true background (shirt whites are slightly tinted), strips floor shadows, defringes and feathers the edge.
- `gen_pawn_pages.py` — regenerates the four Pawn pages from the processed images (import-safe; also owns the shared announcement-bar HTML, kept in sync by hand across pages).
- `make_king_cutouts.py` — cuts every `assets/img/products/*.jpg` (men's studio shots) into `assets/img/king/<name>.webp` for the showcase.
- `gen_home_showcase.py` — builds the homepage showcase. **Adding products:** King → add the product to `tools/catalog/king.json` + photo in `assets/img/products/`, run `make_king_cutouts.py`, `gen_king_page.py`, then this script. ### Mascot — "Sir Checkmate" (`js/mascot.js`)
Original 3D mascot (glossy inflated gentleman: brass king's crown, monocle, burgundy bow tie) built from primitives with three.js (vendored `js/vendor/three-0.159.module.min.js`, loaded ~1s after page load). **Small, free-floating, NOT scroll-driven and not confined to the hero** (user's explicit asks): a 210×250 (150×180 on phones) click-through canvas, moved with a CSS transform, that **sweeps diagonally across the screen** — enters below the bottom edge, crosses 55–95% of the width in a lazy S-curve while rising, dissolves near the top, rests 1–2.5 s, then sweeps back the other way (bottom-left→top-right, then bottom-right→top-left, random start/width each time; ~17–23 s per sweep) — so over time he covers the whole homepage at any scroll position. Turns to face his direction of travel, banks, waves. **Groove:** a soft beat (~2.4 s, `GROOVE` constants) pulses his forward speed (surge/glide), lifts him in a small hop, and times a slight squash-and-stretch, head nod and arm/leg swing — deliberately subtle ("the slightest groove"). Pace/pauses/crossing/sway are the `RISE` constants, size is `SIZE()` + `.mascot-canvas`, look is `buildMascot()`. Skipped for reduced-motion; pauses when the tab is hidden. Test hooks: `window.__mascotFrame(ms)` drives a frame; `window.__mascotSeek(sec)` fast-forwards his clock (handy when the browser pane reports the page as hidden and never runs animation frames). Created because the user liked a floating 3D figure on stripe.press and wanted an original company character.

Below 1240px the links are replaced by the animated `McButton` hamburger. It is `position: sticky; top:0` on every page and screen size. `--hdr-h` (73px, 64px phones) is the header height; the hero pull-ups use it. The old Account button, Pawn dropdown and the first "dark" hamburger menu were removed; the old `.main-nav`/`.nav-toggle`/`.nav-dropdown` CSS in earlier blocks is dead but left in place.
- **Hover panel** (`.mega`, desktop): hovering/focusing a category opens a full-width white panel under the header with columns (Featured / Style / Color swatches / Occasion for men; Shop by cut + Color for kids; product lists for accessories and shoes), two image tiles, and a help row. All of it is the `MEGA` constant at the top of `js/nav.js` — edit labels, links and tiles there. Colour/style/occasion/pattern/price links deep-link into the shop filters: `js/shop.js` reads `?color=&occasion=&style=&pattern=&min=&max=&sort=` (comma-separated). Kids colour swatches link to the Pawn cut that has the most pieces in that colour. Accessories/shoes columns list real products from the search index and jump to the card (`bishop.html#the-en-passant`; `gen_nav.py` stamps those ids).
- **Placeholder pages (e.g. Husky Fit):** a page with no products yet is a `PAGES[...]` entry in `tools/gen_info_pages.py` (glyph hero + one-line "coming soon"; `parent=("Pawn","pawn.html")` gives it the breadcrumb Home / Pawn / Husky Fit) plus a line in `PLACEHOLDER_PAGES` in `tools/gen_pawn_pages.py`, which puts a "Coming soon" card and dropdown option on `pawn.html` (the style cards/options are generated between `STYLE-CARDS` / `STYLE-OPTIONS` markers) and a button on the other Pawn pages. The menus pick it up automatically and mark it "Soon". `pawn-husky.html` is the sample: when the husky photography is processed (raw sets already in `~/Downloads/Magen Kids`: `Regular Husky Suit (ST-H)` 6 colours, `TX-1026H` 4 colours, `DP-26H` dress pants 4 colours), turn it into a normal product page like the other four. Husky sizes/prices are not decided yet.
- **Phones/tablets**: the hamburger opens a light accordion with a search bar on top. Inside each category, in this order: **Shop all <category>** (counts every product page of that department), **Product pages** (every listing page of the department with its item count and "from $" price, e.g. Kids → Slim Fit, Suit Vest Set, Tuxedo, Tuxedo Vest Set), the browse-by links (Style / Color / Occasion…), then **Highlights**. Keep it plain — the user rejected a darker, busier menu with a "Build your look" customizer as "too much contrast and confusing".
- **Self-updating menu:** `tools/gen_nav.py` has a `DEPTS` list (one line per category: key, file prefix, label, chess name, landing page) and **auto-discovers** every `<prefix>.html` / `<prefix>-*.html` page that has a `.cat-hero`, counting its products. It writes that into `js/search-index.js` (`nav` + `products`), refreshes the header links on every page, and every generator (`gen_pawn_pages.py`, `gen_king_page.py`, `gen_info_pages.py`) calls it when it finishes. So a **new product page** (e.g. `pawn-bow-ties.html` or `king-shirts.html`, with a breadcrumb `<span>` naming it) appears in the hamburger menu, the Kids/Men panel, search and breadcrumbs as soon as a generator or `python3 tools/gen_nav.py` runs — commit the regenerated files. A **new category** = add one line to `DEPTS` (and, if you want hand-written columns/tiles in the desktop panel, a `MEGA` entry in `nav.js`; without one it gets an auto-built panel).
- **Search** (header icon, `/` or Ctrl/Cmd+K, plus the bar in the mobile menu): client-side over `js/search-index.js`, which **`tools/gen_nav.py` generates** from the finished king/pawn/bishop/rook pages plus the curated `PAGES` / `HELP` lists in that script (add keywords there when a page or policy changes). `gen_nav.py` also stamps breadcrumb JSON-LD on every page with `.crumbs`.
- **Generator order matters:** run `gen_king_page.py` / `gen_pawn_pages.py` / `gen_info_pages.py` first and `gen_nav.py` last (the others rewrite their pages and drop the JSON-LD). `nav.js?v=N` is cache-busted by hand (currently v=19) alongside `style.css?v=N`.
- Follows the "8 navigation examples that drive conversions" checklist (≤2-level dropdown, consistent placement, minimal header, breadcrumbs, visual menus, hover previews, sticky menu, animated hamburger, easy mobile search, one contrasting CTA). The hamburger markup is the user's `McButton` snippet; only its markup was supplied, so the open/close animation (bars → X, brass ring) is our own.

### Antonio Uomo (dropship supplier) — migrated catalog under Men
Antonio Uomo (antoniouomo.com) is the company the user dropships for. Its whole men's catalog (145 suits, tuxedos, dress pants and jackets, 940 photos) lives on the site as **Men → Antonio Uomo → product type → individual colour pages**:
- **Categories (labels = the user's own list, shown identically in the menus, the pills on every Antonio page and the page titles):** Shop All, 2 Piece Slim Fit Suits, 3 Piece Slim Fit Suits, 3 Piece Classic Fit Suits, Plaid Suits, Textured Suits, 2 Piece Tuxedo, 3 Piece Tuxedo, Jackets, Pants — defined by `suit_info.CATEGORIES` (supplier style name -> category). `antonio-uomo.html` is **Shop All** (every piece, filter by category/colour/price), `antonio-uomo-<category>.html` ×9 list one category, and each colour has a page named "<Colour> <Style name>" (file `antonio-uomo-<style>-<colour>-<code>.html`) with photo gallery, price, size/length picker ("Add to preview bag"), details, the supplier's design copy and the size chart pop-up. These subcategory pages have **no hero** (just breadcrumb, title and category pills, then products). In the menus the brand is a dropdown that starts closed (desktop panel and phone menu) and opens when the customer taps it: Men → Brands → Antonio Uomo ▾ → the categories above. `king.html` is Shop all men and the menus list the brand under Men.
- **Pipeline:** `tools/au_fetch.py` reads the supplier's public `products.json`, writes `tools/catalog/antonio-uomo.json`, downloads **every original photo** into `~/Downloads/Antonio Uomo/<Category>/<Colour Style name (code)>/NN.jpg` (existing files are kept; the 20 older code-named folders there are the user's and are never touched) and writes web copies to `assets/img/antonio-uomo/` (content-addressed by md5 so shared images are stored once: `<md5>.webp` 900px, `-c` 480px card, `-t` 160px thumb). `tools/gen_antonio.py` builds all the pages from the JSON (and runs `gen_nav.py`). To refresh: `python3 tools/au_fetch.py && python3 tools/gen_antonio.py`.
- **Prices are the supplier's listed prices, copied as placeholders** ($39 pants, $99 jackets and 2-piece suits, $139 3-piece slim/classic, $179–219 tuxedos, $199 textured, $239 plaid) — they do not follow the cost-based $179–249 King pricing; the user still has to set their own markup. We did **not** copy the supplier's strike-through "was" prices, testimonials (other people's reviews), FAQ or shipping/alteration/return policy (our own `shipping-returns.html` applies).
- Bag ids are `antonio-uomo/<slug>`, so these items are **not** counted by the groomsmen bulk discount (that only counts `king/` ids) — decide with the user before extending it, margins are unknown.
- **Size charts are per product, never universal** (user rule: our business sells different suppliers' pieces, so there is no site-wide size guide for these). Every product page has a "Size chart" link under the size/length pickers that opens a pop-up (`<dialog id="sizeChart">`) with *that product's* chart. Which chart a product gets is read from the supplier's own product page (the "Size Chart" pop-up image; `au_fetch.py` stores its id in `chart`, `python3 tools/au_fetch.py --charts-only` refreshes it) and the chart data is transcribed in `tools/au_sizes.py` `CHARTS` (exact values as printed, inches; rebuilt as a clean table, not their image). Currently all 145 Antonio Uomo products use one chart, "SIZE-CHART-MAY-3" (XS 36R … 4XL 56R: jacket shoulder / chest / jacket length / sleeve length, pants waist / pants inseam length, the "pick a jacket chest 2–3 in bigger than your chest" notice, and where each measurement is taken). If the supplier adds another chart, transcribe it under its id; a product whose chart has no data gets no pop-up and the generator warns. `size-guide.html` stays the general King/Kids guide and has no Antonio chart.
- Sizes/lengths per product come from the supplier options (34–56, up to 62 for classic fit, pants 30–42; Short/Regular/Long). One title had no colour: style 560811 is named "Dark Teal" (our reading of the photos).
- **The ten chess-named pieces from `tools/catalog/king.json` are regular Antonio Uomo products:** each is filed under one of the categories below and named like the rest ("<Colour> <Style name>", e.g. *Black 2 Piece Slim Fit Tuxedo*), with its chess name and notation (*The Sicilian · Opening 1. e4*) shown where the supplier's style number would be; the mapping is `OPENING_AS` in `tools/gen_antonio.py` (tuxedos treated as 2-piece). They keep their own prices and photos and the same sizing, size chart pop-up and product info as every piece (`tools/suit_info.py`). Cart ids stay `king/<slug>`, so the groomsmen discount still applies to them (and only them). There is no "The Openings" category any more.
- **Filters on every men's grid (Shop all men, Antonio Uomo Shop All, each category): Colour, Style, Pattern, Occasion, Price** (a group with a single value hides itself, so each category only shows the ones that vary). The ten chess-named pieces carry their own Style/Pattern/Occasion from `king.json`; the 145 scraped pieces get **first-pass guesses** from `STYLE_OF` / `pattern_of()` / `occasions_of()` in `tools/gen_antonio.py` (Style: Two-piece, Three-piece, Tuxedo, Jacket, Pants; Pattern: Solid, Shiny, Plaid, Check, Textured, Patterned; Occasion: Black tie, Wedding, Prom, Business, Formal, Summer — e.g. classic-colour tuxedos get Black tie, light suits get Summer). They are not supplier data — the user should refine them. Deep links: `king.html?style=&pattern=&occasion=&color=&min=&max=&sort=`.
- **Photo frames must be filled by the photo, never show their own colour:** the main photo frame (`#pdpFrame`) takes the exact aspect ratio of the photo on show (`--r`, set from each thumbnail's `data-w`/`data-h` by `js/product.js`) with `object-fit: cover`, so there are no letterbox bars; card/tile/thumbnail frames also use `cover`. Do not go back to `object-fit: contain` on product photos.
- `js/product.js` drives the product pages; `shop.js` got more swatch colours (charcoal, silver, beige, gold, teal, indigo).

- Don't make the exploding-diagram scroll-scrubbed again — it triggers once on scroll-into-view.
